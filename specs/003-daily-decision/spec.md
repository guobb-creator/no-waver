## 1. 文档信息

| 项目 | 内容 |

## 2. 背景与目标

当前产品已支持“旅行”板块：用户输入一段自然语言，系统围绕旅行目的地选择给出对话式建议，并在旅行场景中接入高德地图路线数据。

本次增量希望实现“日常”板块，让产品从单一旅行决策扩展为更通用的生活选择助手。日常板块用于处理用户生活中轻量、低风险、非专业领域的两难或多选问题，例如：

- 今天晚饭吃什么；
- 周末做什么；
- 下班后去健身还是休息；
- 买哪件普通日用品；
- 先做哪件日常小事；
- 和朋友约哪种活动。

本版本目标不是做严肃咨询、专业建议或复杂决策系统，而是延续“对话式产品”的核心体验：

```text
用户选择“日常”分类 → 输入一段日常纠结 → 系统给出理性比较与建议
```

## 3. 产品定位

“日常”板块与“旅行”板块的关系：

| 项目 | 旅行板块 | 日常板块 |
| --- | --- | --- |
| 典型问题 | 下午去 B 还是 C | 今天/现在/近期做 A 还是 B |
| 数据来源 | 高德地图路线数据 + 模型已有知识 | 本期仅模型已有知识 |
| 输出方式 | 路线对比 + 优缺点 + 建议 | 选项对比 + 优缺点 + 建议 |
| 输入方式 | 单段自然语言 | 单段自然语言 |
| 交互轮次 | 单轮 | 单轮 |
| 结果展示 | 纯文本 | 纯文本 |

日常板块应保持产品整体调性：轻、快、清楚、有判断，但不替用户承担高风险决策责任。

## 4. 本期目标

本期希望实现：

1. 用户可以在页面分类中选择“日常”。
2. 用户在“日常”板块输入一段自然语言日常决策问题。
3. 系统识别用户想比较的选项、关注点和约束。
4. 系统以中文纯文本形式给出：
   - 对选项的简短比较；
   - 每个选项的优缺点；
   - 适合选择该选项的条件；
   - 一个明确建议。
5. 若用户输入信息不足、选项不明确或问题不适合本产品回答，系统应提示用户补充或改写。

## 5. 本期包含

### 5.1 分类切换

1. 页面已有“日常”“旅行”分类入口。
2. 本期需要让“日常”成为可选分类，而不是静态按钮。
3. 用户选择“日常”后：
   - 输入区标题切换为日常决策相关文案；
   - 输入帮助文案切换为日常决策相关文案；
   - 默认输入示例可切换为日常示例；
   - 提交后调用日常决策逻辑。
4. 分类切换时，应保留每个分类已有的用户输入和模型回复。该保留仅指当前浏览器页面会话内的前端状态，不做服务器保存、账户绑定或持久化历史。

### 5.2 日常输入

日常板块仍使用一个 `textarea`，用户可以自然输入，例如：

```text
我今晚纠结是自己做饭还是点外卖，想省钱但也不想太累，明天还要早起。
```

输入可以包含：

- 候选选项，例如“做饭 / 点外卖”；
- 当前状态，例如“很累、时间不多、预算有限”；
- 关注点，例如“省钱、健康、省时间、开心、效率、舒适度”；
- 时间背景，例如“今晚、周末、下班后、今天中午”。

### 5.3 日常输出

成功回复应保持中文纯文本，建议包含：

1. 先简短复述用户的核心纠结；
2. 分别说明每个选项的优点和缺点；
3. 根据用户关注点给出判断；
4. 明确推荐一个选项；
5. 如适合，可给一个轻量执行建议。

示例：

```text
你现在主要是在“省钱和健康”与“省时间和省精力”之间纠结。

自己做饭的优点是更省钱、更健康，也更可控；缺点是要花时间准备和收拾，今晚如果已经很累，执行成本会偏高。
点外卖的优点是省时间、省精力，适合明天要早起的情况；缺点是花费更高，也可能没那么健康。

我的建议：今晚点一份相对清淡、价格适中的外卖。因为你明天还要早起，今天的核心矛盾不是“最省钱”，而是减少消耗、早点休息。下次时间更充裕时再自己做饭。
```

## 6. 本期不包含

以下能力不属于本期：

- 多轮追问或连续对话；
- 账户、历史记录、收藏、复盘；
- 用户自定义权重滑块或复杂评分模型；
- 日历、天气、地图、购物、点评、搜索、价格比对等外部工具调用；
- 自动读取用户位置、日程、账单、健康数据或其他个人数据；
- 严肃医疗、法律、金融、心理危机、职业重大决策等高风险建议；
- 替用户执行外部操作，例如下单、预约、发消息、创建日程；
- 多人协作决策或投票。

## 7. 用户故事与验收标准

### US-006：选择日常分类

**作为** 一个有日常小纠结的用户，  
**我希望** 可以在“日常”和“旅行”之间切换，  
**以便** 让系统按当前问题类型给出更合适的建议。

验收标准：

1. 页面显示“日常”和“旅行”分类。
2. 用户可以点击“日常”。
3. 被选中的分类有明确视觉状态。
4. 切换到“日常”后，输入区标题、帮助文案和默认示例应与日常决策一致。
5. 切回“旅行”后，旅行板块现有能力不受影响。

### US-007：输入日常决策问题

**作为** 一个正在纠结日常选择的用户，  
**我希望** 用一段自然语言描述我的选项和关注点，  
**以便** 系统帮我整理怎么选。

验收标准：

1. 日常板块提供单个可编辑输入区域。
2. 用户可以输入两选一或多选一的日常问题。
3. 输入为空或仅空白时不能提交，或提交后得到明确提示。
4. 若用户没有提供可比较的选项，系统应提示用户补充选项。
5. 若用户只写“我该怎么办”但没有背景，系统应提示用户补充场景、选项或关注点。

### US-008：查看日常建议

**作为** 已提交日常问题的用户，  
**我希望** 看到简短、有判断的比较和建议，  
**以便** 更快做出决定。

验收标准：

1. 成功回复为中文纯文本。
2. 回复应包含对主要选项的优缺点分析。
3. 回复应结合用户关注点，例如时间、预算、体力、心情、效率、健康、风险等。
4. 回复应给出明确建议，而不是只罗列利弊。
5. 回复语气应轻量、直接、像一个理性朋友，不应过度严肃或说教。

### US-009：拒绝或引导高风险问题

**作为** 用户，  
**我希望** 当我的问题不适合由轻量日常助手回答时，系统能明确提示，  
**以便** 我知道需要换一种方式或寻求专业帮助。

验收标准：

1. 当问题涉及医疗诊断、用药、法律结论、投资建议、严重心理危机、人身安全等高风险场景时，不应给出直接决策建议。
2. 系统应提示该问题超出日常轻量决策范围。
3. 系统可建议用户补充普通日常选择问题，或寻求专业人士帮助。
4. 本期暂不展示独立免责声明，但回复中应避免装作专业判断。

## 8. 页面与交互要求

### 8.1 分类状态

页面分类区建议行为：

- “旅行”为当前已实现分类。
- “日常”为本期新增分类。
- 点击分类后，当前分类高亮。
- 分类切换不需要页面跳转。
- 分类切换时可以替换输入框内容为该分类默认示例。

本期采用以下规则：

- 每个分类维护自己的当前输入草稿和最近一次模型回复；
- 首次进入分类时显示该分类默认示例；
- 切回分类时恢复该分类上次输入和回复；
- 刷新页面后不恢复历史。

### 8.2 日常默认示例

建议日常默认示例：

```text
我今晚纠结是自己做饭还是点外卖，想省钱但也不想太累，明天还要早起。请帮我比较并建议我怎么选。
```

### 8.3 日常输入区文案

建议日常输入区标题：

```text
说说你在纠结什么，我帮你做决定。
```

建议日常帮助文案：

```text
请说明你的选项、当前状态和主要关注点，例如时间、预算、精力、心情或风险。
```

旅行板块现有文案保持不变。

## 9. 模型调用与数据边界

1. 日常板块仍通过服务端模型客户端调用模型。
2. 浏览器端不得持有模型密钥。
3. 本期日常板块不调用地图、高德、搜索、购物、点评、日历、天气或其他外部数据服务。
4. 模型只基于用户输入和模型已有知识进行日常建议。
5. 模型不得声称查询了实时价格、库存、天气、门店、人流、健康数据等外部信息。
6. 每次提交仍为单轮独立请求，不维护多轮上下文。
7. 不持久化保存用户输入或模型回复；分类切换时的保留仅限当前页面会话内的前端状态。

## 10. API 与实现边界

当前已有 `POST /api/decision` 用于旅行决策。为了方便后续维护，本期日常板块使用独立后端接口。

### 已确认方案：新增 `/api/daily-decision`

示例：

```json
{
  "question": "我今晚纠结是自己做饭还是点外卖……"
}
```

优点：

- 日常和旅行后端边界清晰；
- 后续增加更多分类时更易维护；
- 旅行接口可以继续专注地图路线决策；
- 日常接口可以独立处理低风险/高风险问题边界。

缺点：

- 前端需要按分类选择不同接口；
- 测试需要覆盖两个接口。

### 暂不采用方案：复用 `/api/decision` 并增加 `category`

优点：

- 接口数量更少；
- 可复用现有旅行接口入口。

缺点：

- 单个接口需要按分类分流；
- 旅行地图逻辑和日常轻量逻辑容易耦合；
- 后续分类增加后维护成本更高。

## 11. 异常处理文案方向

信息不足：

```text
我还不知道你具体在比较哪些选项。请补充你正在纠结的 2 个或多个选择，以及你最在意的点，比如时间、预算、精力或心情。
```

问题过于宽泛：

```text
这个问题有点宽泛，我需要更多背景才能帮你判断。你可以告诉我：现在的场景是什么、有哪些选项、你最担心或最在意什么。
```

高风险问题：

```text
这个问题超出了日常轻量决策的范围，我不适合直接替你做决定。建议你先咨询相关专业人士；如果你愿意，也可以把它改写成一个普通日常选择问题，我可以帮你整理利弊。
```

## 12. 已确认事项

1. 日常板块只处理低风险、轻量生活选择。
2. 日常板块本期不调用任何外部工具，只使用模型已有知识。
3. 分类切换时保留每个分类已有的用户输入和模型回复；该保留仅限当前页面会话，不做持久化保存。
4. 日常默认示例采用第 8.2 节文案。
5. 日常输入区标题采用“说说你在纠结什么，我帮你做决定。”。
6. 后端采用独立接口 `/api/daily-decision`，不与旅行接口混写。
