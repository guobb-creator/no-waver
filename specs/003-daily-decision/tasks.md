## 2. 实施约束

- 本期实现“日常”分类，并保留“旅行”分类现有能力。
- 日常只处理低风险、轻量生活选择。
- 日常不调用任何外部工具或数据服务，只调用模型服务。
- 日常后端使用独立接口 `POST /api/daily-decision`，不与旅行接口混写。
- 分类切换时保留每个分类当前页面会话内的用户输入和最近一次模型回复。
- 不做账户、历史记录、数据库、浏览器持久化保存或跨刷新恢复。
- 结果仍为中文纯文本。
- 仍为单轮交互。
- 前端不得暴露模型密钥。
- 不改动旅行地图路线查询、占位符地点拦截和降级逻辑，除非为了接入分类状态做必要前端调用调整。

## 6. 实现完成定义

只有在 T001–T018 完成且以下条件全部满足时，才可将本规格标记为“已实现”：

- 用户可以点击“日常”和“旅行”切换分类；
- 日常分类展示确认的标题、帮助文案和默认示例；
- 日常提交调用独立 `/api/daily-decision`；
- 日常回复包含选项优缺点和明确“我的建议”；
- 日常信息不足时提示补充选项和关注点；
- 日常高风险问题不直接给决策建议；
- 切换分类时保留各自当前输入和最近一次回复；
- 刷新页面后不恢复历史；
- 旅行地图路线能力不受影响；
- 日常不调用地图、搜索、购物、点评、天气、日历等外部工具；
- 前端不暴露模型密钥；
- 不持久化保存用户输入或回复；
- `npm run lint`、`npm test`、`npm run build`、`npm run test:e2e` 全部通过；
- 线上真实模型日常冒烟和旅行回归冒烟通过。
