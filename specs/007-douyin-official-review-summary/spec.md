## 2. 背景与目标

用户希望优先使用抖音官方 API 获取游客反馈。相比小红书第三方 API，抖音官方开放平台具备更高的合规确定性，但其关键词视频搜索和评论能力存在权限、关键词管理和授权边界，不一定等同于抖音 App 端任意关键词搜索。

本次增量目标是：基于抖音官方开放平台能力，为每个旅行候选目的地获取相关热视频/评论摘要，帮助用户在高德交通数据之外，参考真实抖音游客反馈。

目标链路：

```text
候选目的地 → 抖音官方关键词视频搜索 → 获取公开视频/评论信息
→ 生成视频/评论摘要 → 前端展示游客反馈参考
→ 用户可浏览器预览或打开抖音核验
```

## 3. 官方能力边界

### 3.1 关键词视频搜索

抖音开放平台提供关键词视频搜索相关能力，可通过关键词搜索标题中含对应词组的公开视频。公开文档说明：

- 使用前需要在管理中心创建/申请关键词；
- 搜索能力通常围绕“与我相关”的关键词；
- 接口结果可能受时效限制，例如只返回最近一段时间的视频；
- 能力需要在抖音开放平台申请。

因此，本期不能默认假设“任意景点名都能直接搜索全站视频”。实现前必须确认关键词管理和能力权限。

### 3.2 评论能力

抖音开放平台存在视频评论相关接口，但通常需要申请权限和用户授权，具体 scope/能力取决于应用类型与接口版本。

因此，本期把评论摘要设计为“可选增强”：

- 如果评论权限可用，则摘要可综合视频标题/描述/评论；
- 如果评论权限不可用，则只基于公开视频标题、描述、互动数据生成摘要；
- 不得编造评论内容。

## 4. 本期目标

1. 优先使用抖音官方开放平台 API，不使用第三方抖音数据 API。
2. 对两个候选目的地分别搜索相关抖音视频。
3. 每个目的地最多展示 3 条高互动视频。
4. 每条视频生成一句游客反馈摘要。
5. 每条视频提供两个入口：
   - 浏览器预览；
   - 打开抖音。
6. 摘要、浏览器链接、App 跳转链接必须绑定同一个抖音视频标识。
7. 页面新增“抖音游客反馈参考”区域。
8. 小红书第三方 API 方案暂不进入实现，后续可作为另一个 review provider。
9. 高德交通摘要保持不变。

## 5. 本期包含

### 5.1 抖音搜索策略

默认搜索关键词：

```text
{城市线索} {目的地名称} 游玩
{城市线索} {目的地名称} 攻略
{城市线索} {目的地名称} 值得去吗
```

由于抖音官方关键词搜索需要提前管理关键词，本期实现前需确认：

- 是否能为用户动态目的地创建关键词；
- 关键词审核/生效是否实时；
- 是否只能使用预先配置的关键词；
- 是否支持“杭州 灵隐寺 游玩”这类长尾关键词。

如果只能使用预设关键词，则本期仅支持已配置目的地关键词。

### 5.2 视频筛选

每个目的地搜索候选视频后，按以下规则筛选：

- 优先高互动视频；
- 标题/描述与目的地强相关；
- 过滤广告、带货、明显无关视频；
- 过滤没有可核验视频 ID 或跳转链接的视频；
- 最多展示 3 条。

### 5.3 摘要生成

每条视频生成一句摘要，依据优先级：

1. 视频标题；
2. 视频描述/文案；
3. 官方 API 返回的互动数据；
4. 评论摘要（仅在官方评论权限可用时）。

摘要要求：

- 30–60 字；
- 只基于官方 API 返回的数据；
- 不声称“抖音用户普遍认为”，除非有评论摘要支撑；
- 不编造视频中没有的信息。

示例：

```text
这条视频主要强调灵隐寺适合祈福和拍照，但从标题/文案看更像完整半日游，下午时间紧时需要预留路程。
```

### 5.4 视频标识一致性

每条视频必须以官方返回的视频标识作为信任锚点。

候选字段：

- `itemId`
- `videoId`

规则：

1. 搜索结果必须包含可核验视频标识。
2. 摘要只基于该视频标识对应的数据生成。
3. 浏览器预览链接和 App 跳转链接必须指向同一视频。
4. 若官方提供“视频详情页跳转链接获取”接口，优先使用官方返回链接/schema。
5. 若无官方跳转链接，则该视频只展示可核验的官方返回网页链接。

### 5.5 前端展示

推荐顺序：

```text
交通对比
……

抖音游客反馈参考
数据来源：抖音官方开放平台

灵隐寺
1. 《标题》
   摘要：……
   赞/评/发布时间
   [浏览器预览] [打开抖音]

岳王庙
……

给你的建议
……
```

### 5.6 AI 回复约束

模型最终建议可以使用：

- 高德交通摘要；
- 抖音官方视频/评论摘要；
- 用户原始输入。

模型不得：

- 编造抖音 API 未返回的游客反馈；
- 把单条视频说成整体趋势；
- 在评论权限不可用时声称“评论区都说”；
- 在抖音 API 失败时声称使用了抖音反馈。

## 6. 本期不包含

- 小红书第三方 API 实现；
- 抖音第三方数据 API；
- 自动创建/审核抖音关键词的运营流程自动化；
- 评论全文深度分析；
- 视频播放内嵌；
- 下载或缓存视频文件；
- 展示视频封面大图；
- 用户登录抖音授权；
- 保存历史记录；
- 多于两个候选目的地。

## 7. 异常与降级

| 情况 | 产品行为 |
| --- | --- |
| 抖音 API 未配置 | 不展示抖音反馈；AI 不引用抖音数据 |
| 关键词未配置/未通过 | 提示该目的地暂未配置抖音关键词 |
| 某目的地不足 3 条有效视频 | 展示已有视频并说明数量不足 |
| 某目的地 0 条有效视频 | 该目的地展示“暂未获取到可靠抖音视频反馈” |
| 评论权限不可用 | 只基于视频标题/描述/互动数据摘要 |
| 视频跳转链接不可用 | 不展示该视频或只展示浏览器预览 |
| 抖音全部失败 | 保留高德交通摘要；AI 不引用抖音反馈 |

## 8. 用户故事与验收标准

### US-021：查看抖音游客反馈摘要

**作为** 正在旅行中做选择的用户，  
**我希望** 看到每个目的地的抖音相关热视频摘要，  
**以便** 快速了解真实游客反馈。

验收标准：

1. 旅行成功结果中展示“抖音游客反馈参考”。
2. 每个目的地最多展示 3 条视频。
3. 每条视频展示标题、摘要和互动信息。
4. 页面明确显示数据来源为抖音官方开放平台。

### US-022：打开摘要对应的抖音视频

**作为** 用户，  
**我希望** 可以打开摘要对应的视频，  
**以便** 核验摘要是否可信。

验收标准：

1. 每条视频提供“浏览器预览”入口。
2. 能获取官方 schema 时，提供“打开抖音”入口。
3. 两个入口与摘要使用同一视频标识。

### US-023：抖音权限不足时不制造幻觉

**作为** 用户，  
**我希望** 当抖音数据不可用时，系统不要假装使用了抖音反馈，  
**以便** 我知道建议依据是否可靠。

验收标准：

1. 抖音 API 失败或权限不足时，不展示伪造摘要。
2. AI 建议不得出现“根据抖音反馈”之类表达。
3. 页面仍可展示高德交通摘要。

## 9. 待确认问题

1. 你是否已经有抖音开放平台应用？应用类型是网站应用、移动应用还是小程序？
2. 是否能申请/已申请“关键词视频搜索”或“视频搜索管理”能力？
3. 关键词是否可以动态创建，还是必须预先配置？
4. 评论能力是否需要本期接入？如果权限难拿，是否先只基于视频标题/描述/互动数据做摘要？
5. 每个目的地是固定 3 条，还是最多 3 条、不足也展示？
6. 是否展示点赞、评论、发布时间？
7. 浏览器预览和打开抖音是否优先使用官方“视频详情页跳转链接获取”接口返回的链接/schema？
8. 抖音全部失败时，是否允许继续基于高德交通 + 模型通用知识给建议，但明确“不含抖音真实反馈”？
