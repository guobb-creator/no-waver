# 产品规格：旅行内嵌高德路线确认区

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 不再摇摆 |
| 规格编号 | `004-embedded-amap-route-confirmation` |
| 关联规格 | `001-mvp-decision-loop`、`002-distance-aware-decision`、`003-daily-decision` |

## 2. 背景与目标

旅行模块当前已经接入高德地图路线数据，并用纯文本展示 A→B、A→C 的交通方式与预计时间。用户仍然需要在产品和高德地图之间切换，才能查看更完整的路线细节并开始导航。

本次增量希望在旅行结果中加入“高德路线确认区”：用户看到 AI 决策建议后，可以直接在当前页面内查看高德路线页面，并可一键跳转到高德地图继续导航。

产品目标不是复刻完整地图导航产品，而是减少用户在“不再摇摆”和“高德地图”之间来回切换的成本：

```text
AI 先帮用户做选择 → 页面内嵌高德路线供用户确认 → 用户需要出发时跳转高德导航
```

## 3. 核心原则

### 3.1 接受方案 A：内嵌高德 H5/URI 路线页

本规格采用“方案 A”：在旅行建议结果下方内嵌高德路线页面，尽量呈现接近高德 App 路线选择页的体验。

高德 URI API 支持通过 URL 形式进行路径规划，覆盖驾车、公交、步行、骑行等方式，并支持移动端通过 `callnative=1` 尝试调起高德地图 App。参考：

- 高德 URI 路径规划文档：https://lbs.amap.com/api/uri-api/guide/travel/route
- 高德 URI 入门指南：https://lbs.amap.com/api/uri-api/gettingstarted

### 3.2 一致性边界

由于内嵌高德页面会由高德页面自身执行路线展示或重新计算，AI 结论使用的后端高德 Web Service 数据与内嵌高德页面显示的数据无法保证 100% 完全一致。

本期采取“尽量一致 + 明确说明”的策略：

1. AI 结论、内嵌高德页面、打开高德导航链接尽量使用同一组高德坐标。
2. 内嵌页面的默认目的地和交通方式应与用户当前查看的路线一致。
3. AI 文案使用“约 X 分钟”“本次路线数据看”等表达，避免绝对化。
4. 页面明确提示：AI 建议基于本次高德路线数据生成，下方高德路线页用于实时确认，实际导航以高德页面为准。
5. 若内嵌高德页面与 AI 结论存在轻微差异，以高德页面和高德 App 的实时导航为准。

### 3.3 不引入小红书

本期只考虑高德，不接入小红书、不展示小红书链接、不读取小红书帖子。

## 4. 本期目标

1. 旅行结果成功时，在 AI 文本建议下方展示“高德路线确认区”。
2. 用户可在两个候选目的地 B/C 之间切换。
3. 用户可在支持的交通方式之间切换：
   - 公交/地铁；
   - 驾车/打车；
   - 骑行；
   - 步行。
4. 页面内嵌高德路线页面，用于查看更完整的路线。
5. 提供“打开高德地图导航”按钮，允许用户跳转到高德地图 App 或高德 H5 页面。
6. 增加路线置信度或依据说明，让用户知道 AI 建议和高德路线确认区之间的关系。
7. 当地点无法识别、地图数据不可用或高德页面无法嵌入时，页面不崩溃，并给出可理解的降级提示。

## 5. 本期包含

### 5.1 旅行结果结构扩展

当前 `POST /api/decision` 成功响应为：

```json
{
  "status": "success",
  "message": "中文纯文本建议",
  "maxInputChars": 12000
}
```

本期需要在成功响应中增加可选路线确认数据：

```json
{
  "status": "success",
  "message": "中文纯文本建议",
  "maxInputChars": 12000,
  "routeConfirmation": {
    "origin": {
      "name": "杭州西湖",
      "location": "120.148,30.247"
    },
    "candidates": [
      {
        "id": "candidate-0",
        "name": "灵隐寺",
        "location": "120.102,30.240",
        "availableModes": ["transit", "driving", "cycling", "walking"]
      },
      {
        "id": "candidate-1",
        "name": "岳王庙",
        "location": "120.140,30.253",
        "availableModes": ["transit", "driving", "cycling", "walking"]
      }
    ],
    "defaultCandidateId": "candidate-1",
    "defaultMode": "transit",
    "confidence": {
      "level": "high",
      "reason": "两个目的地均成功匹配到高德路线数据，推荐目的地在多种交通方式上更省时。"
    }
  }
}
```

注意：

- `routeConfirmation` 只在旅行模块成功获取地图路线数据时返回。
- 地图失败并降级为模型常识建议时，不展示内嵌高德确认区，或展示“暂时无法嵌入高德路线”的提示。
- 不向前端返回高德 Key 或原始高德 API 响应。

### 5.2 高德路线确认区

旅行结果区建议拆成两部分：

1. AI 建议文本；
2. 高德路线确认区。

示例结构：

```text
给你的建议

路线对比：
……

我的建议：选岳王庙。

高德路线确认
AI 建议基于本次高德路线数据生成；下方为高德路线页，实际导航以高德为准。

[灵隐寺] [岳王庙]
[公交/地铁] [驾车/打车] [骑行] [步行]

内嵌高德路线页面

[打开高德地图导航]
```

### 5.3 内嵌高德页面

优先尝试使用高德 URI 路径规划页面作为内嵌内容。

行为要求：

- 使用高德坐标而不是纯地点文本生成 URL；
- 目的地切换时刷新内嵌路线 URL；
- 交通方式切换时刷新内嵌路线 URL；
- 移动端高度适中，避免页面被地图完全占满；
- 若 iframe 被高德限制加载，应展示 fallback 卡片和“打开高德地图导航”按钮。

### 5.4 跳转高德导航

按钮文案建议：

```text
打开高德地图导航
```

行为：

- 移动端优先尝试调起高德 App；
- 若无法调起，则打开高德 H5 路线页；
- 桌面端打开高德 H5 路线页；
- 使用当前选中的目的地和交通方式。

### 5.5 置信度与依据说明

建议展示轻量说明：

```text
置信度：较高
原因：两个目的地均成功匹配到高德路线数据，且推荐目的地在多种交通方式上更省时。
```

置信度规则建议：

| 级别 | 条件 |
| --- | --- |
| 高 | 两个目的地均有高德路线数据，且推荐目的地在至少两种主要交通方式上更省时或优势明显。 |
| 中 | 两个目的地均有路线数据，但时间差异不明显，或主要依赖用户偏好/游客评价判断。 |
| 低 | 路线数据不完整、交通方式缺失较多，或地图与地点匹配存在不确定性。 |

## 6. 本期不包含

- 小红书搜索、帖子展示或任何小红书数据接入；
- 用户当前位置自动定位；
- 允许用户在地图中手动拖拽起点/终点；
- 用户在内嵌地图中重新选择 POI；
- 多条路线策略深度对比；
- 实时公交到站、打车价格、天气、营业时间；
- 保存路线、收藏路线或历史记录；
- 自研完整导航界面；
- 高德地图 JS API 绘制自定义路线地图。

## 7. 用户故事与验收标准

### US-010：查看内嵌高德路线确认区

**作为** 正在旅行决策的用户，  
**我希望** 在 AI 建议下面直接看到高德路线页面，  
**以便** 不用立即切到高德也能确认路线是否合理。

验收标准：

1. 当旅行决策成功且路线数据可用时，结果区展示“高德路线确认”。
2. 默认选中系统建议或交通上更优的目的地。
3. 内嵌区域加载高德路线页面。
4. 页面说明“实际导航以高德为准”。
5. 若内嵌页面无法加载，展示 fallback 提示和跳转按钮。

### US-011：切换目的地和交通方式

**作为** 用户，  
**我希望** 可以在 B/C 和不同交通方式之间切换，  
**以便** 快速核验不同路线。

验收标准：

1. 用户可以切换两个候选目的地。
2. 用户可以切换公交/地铁、驾车/打车、骑行、步行中可用的方式。
3. 切换后内嵌高德页面刷新为对应路线。
4. 不可用的交通方式不展示或置灰。

### US-012：跳转高德地图导航

**作为** 已做出选择的用户，  
**我希望** 点击按钮直接打开高德地图导航，  
**以便** 立即出发。

验收标准：

1. 页面提供“打开高德地图导航”按钮。
2. 点击后使用当前选中的目的地和交通方式。
3. 移动端尽量调起高德 App。
4. 桌面端或无法调起 App 时打开高德 H5 页面。

## 8. 待确认问题

1. 内嵌区默认是否展开？
   - 方案 1：默认展开，用户一进结果就看到高德路线；
   - 方案 2：默认折叠，点击“查看高德路线”后展开。
2. 内嵌区默认高度是多少？
   - 建议移动端 520–640px，桌面端 560–720px。
3. 默认选中的交通方式是什么？
   - 方案 1：默认展示 AI 最推荐/最有优势的方式；
   - 方案 2：优先公交/地铁；
   - 方案 3：优先驾车/打车。
4. 如果高德页面不允许 iframe 内嵌，是否接受自动降级为“路线卡片 + 打开高德地图”？
5. 是否要显示置信度？
   - 建议显示，文案短，不做复杂分数。
