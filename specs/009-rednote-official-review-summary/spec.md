# 产品规格：旅行小红书官方帖子摘要

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 不再摇摆 |
| 规格编号 | `009-rednote-official-review-summary` |
| 关联规格 | `005-trusted-traffic-summary`、`008-rednote-search-entry` |
| 版本 | 0.1（待确认） |
| 产品形态 | Web，优先适配手机端浏览器 |
| 目标阶段 | MVP 增量 |
| 状态 | 草案，待官方能力确认 |

## 2. 背景与目标

用户希望优先调用小红书官方 API 搜索相关帖子。如果官方 API 能返回帖子内容，则基于内容生成摘要，并附“小红书查看”链接。

当前公开小红书开放平台文档主要覆盖电商/商家经营类接口，例如公共、商品、订单、售后、库存、素材中心等能力；公开目录中暂未看到通用“按关键词搜索笔记 / 获取任意笔记详情”的官方内容 API。因此本规格以“官方能力可用”为实现前置条件。

目标链路：

```text
目的地 → 小红书官方 API 搜索帖子 → 官方 API 获取帖子详情
→ 若有内容则生成摘要 → 展示摘要 + 小红书查看
```

如果官方 API 只能返回帖子链接、不能返回内容，则只展示“小红书查看”，不生成摘要。

如果官方 API 不支持搜索/详情，本规格不进入实现，回退到 `008-rednote-search-entry`。

## 3. 本期目标

1. 优先使用小红书官方 API，不使用第三方 API。
2. 对两个候选目的地分别搜索相关帖子。
3. 若官方 API 返回帖子内容，则为每篇帖子生成一句摘要。
4. 每篇帖子展示“小红书查看”链接。
5. 摘要和链接必须绑定同一官方帖子标识。
6. 若官方 API 只返回链接不返回内容，则不生成摘要。
7. 若官方 API 不支持搜索/详情，则停止实现并回退到小红书查看入口方案。
8. AI 最终建议只能引用官方 API 返回并已摘要的内容，不得编造小红书反馈。

## 4. 官方能力前置条件

实现前必须确认小红书官方提供以下能力：

| 能力 | 是否必须 | 说明 |
| --- | --- | --- |
| 关键词搜索笔记 | 必须 | 输入目的地关键词，返回相关帖子列表 |
| 帖子唯一标识 | 必须 | 用于保证摘要和链接是同一篇帖子 |
| 帖子查看链接 | 必须 | 用于“小红书查看” |
| 帖子标题 | 可选 | 有标题可提升展示质量 |
| 帖子正文/描述 | 摘要必须 | 没有正文/描述则不能生成摘要 |
| 互动数据 | 可选 | 点赞、收藏、评论数等 |
| 发布时间 | 可选 | 帮助判断内容新旧 |

## 5. 产品行为

### 5.1 官方 API 能返回内容

展示：

```text
小红书游玩体验
以下是灵隐寺和岳王庙的相关游玩分享。

灵隐寺
《标题》
摘要：这篇主要说……
[小红书查看]
```

AI 可以引用这些摘要，但必须说明依据来自“已获取的小红书相关内容摘要”。

### 5.2 官方 API 只能返回链接，不能返回内容

展示：

```text
小红书游玩体验
以下是灵隐寺和岳王庙的相关游玩分享。

灵隐寺
[小红书查看]
```

AI 不引用小红书内容。

### 5.3 官方 API 不支持搜索/详情

不实现本规格，改用 `008-rednote-search-entry`。

## 6. 一致性规则

每条帖子必须有官方帖子标识，例如：

```text
noteId / note_id / itemId
```

规则：

1. 搜索结果返回的帖子标识必须存在。
2. 详情接口必须使用同一个帖子标识。
3. 摘要必须基于同一个帖子标识的详情内容。
4. “小红书查看”链接必须指向同一个帖子。
5. 如果官方返回的链接与帖子标识无法对应，则丢弃该帖子。

## 7. AI 回复约束

模型可以引用：

- 高德交通摘要；
- 小红书官方 API 返回并成功摘要的帖子内容；
- 用户输入。

模型不得：

- 引用未获取到的帖子标题/正文/评论；
- 把搜索链接当成已阅读内容；
- 在只返回链接时说“根据小红书帖子”；
- 在官方 API 不可用时声称使用了小红书反馈。

## 8. 本期不包含

- 第三方小红书 API；
- 抓取网页 HTML；
- 爬虫；
- 评论全文分析；
- 视频/图片下载；
- 小红书登录授权；
- 保存帖子历史；
- 多于两个候选目的地。
