# 产品规格：旅行小红书查看入口

| --- | --- |

## 2. 背景与目标

小红书官方 API 不支持当前产品所需的通用帖子搜索/详情获取；本期也不考虑第三方 API。因此产品不能自动读取帖子标题、正文、评论，也不能生成基于小红书真实内容的摘要。

本次增量只做轻量的小红书查看入口：为每个旅行候选目的地生成小红书搜索入口，让用户可以像点击“高德查看”一样，点击“小红书查看”去查看相关游玩体验。

目标不是让 AI 自动使用小红书内容，而是减少用户手动打开小红书、输入搜索词的成本。

## 3. 本期目标

1. 在旅行结果中新增“小红书游玩体验”区域。
2. 每个候选目的地展示一个“小红书查看”按钮。
3. “小红书查看”打开对应目的地的小红书搜索结果页或 App 搜索页。
4. 不展示搜索词。
5. 不展示“核验”一词。
6. 不抓取、不存储、不解析小红书帖子标题、正文、评论、图片、互动数。
7. AI 最终建议仍基于高德交通数据 + 模型已有通用知识 + 用户输入生成。
8. AI 不得声称使用了小红书实时帖子内容。

## 4. 用户体验

推荐展示位置：

```text
交通对比
……

小红书游玩体验
以下是灵隐寺和岳王庙的游玩体验入口，你可以打开看看近期大家怎么分享。

灵隐寺
[小红书查看]

岳王庙
[小红书查看]

给你的建议
……
```

文案原则：

- 面向 C 端，避免“核验”“抓取”“未读取”等技术或审计感强的词；
- 不暗示产品已经读取小红书内容；
- 不展示搜索词；
- 入口文案与“高德查看”保持一致，使用“小红书查看”。

## 5. 搜索入口生成

服务端或前端基于候选目的地生成搜索 URL。

内部搜索词格式：

```text
{城市线索} {目的地名称} 游玩体验
```

示例：

```text
杭州 灵隐寺 游玩体验
杭州 岳王庙 游玩体验
```

但搜索词不展示给用户。

浏览器入口建议：

```text
https://www.xiaohongshu.com/search_result?keyword={encodedKeyword}
```

如果后续确认更稳定的小红书 App deep link，可增强为优先尝试打开 App；本期先使用一个“小红书查看”链接，逻辑等同“高德查看”：

- 手机浏览器中由小红书页面/系统自行决定是否唤起 App；
- 若不能唤起 App，则停留在浏览器页面；
- 不做双按钮。

## 6. AI 回复约束

本期不获取小红书内容，因此模型不得：

- 说“根据小红书帖子”；
- 说“近期小红书反馈”；
- 说“小红书上大家都说”；
- 编造任何小红书标题、正文、评论、互动数据。

模型可以说：

```text
游客体验部分基于通用认知；你也可以用上方小红书入口看看近期游玩分享。
```

如果产品担心这句太啰嗦，可只在页面区域说明，不要求每次 AI 建议都重复。

## 7. API 响应契约

旅行成功响应新增可选：

```json
{
  "rednoteEntries": {
    "title": "小红书游玩体验",
    "description": "以下是灵隐寺和岳王庙的游玩体验入口，你可以打开看看近期大家怎么分享。",
    "entries": [
      {
        "candidateId": "candidate-0",
        "name": "灵隐寺",
        "url": "https://www.xiaohongshu.com/search_result?keyword=..."
      },
      {
        "candidateId": "candidate-1",
        "name": "岳王庙",
        "url": "https://www.xiaohongshu.com/search_result?keyword=..."
      }
    ],
    "notice": "AI 建议未读取小红书帖子内容，小红书入口用于你查看近期游玩分享。"
  }
}
```

注意：

- `notice` 可作为可访问或辅助说明，不一定在页面主视觉中完整展示；
- 前端不展示搜索词；
- 前端按钮文案固定为“小红书查看”。

## 8. 本期不包含

- 小红书官方 API；
- 小红书第三方 API；
- 抓取搜索结果标题；
- 抓取帖子正文；
- 抓取评论；
- 生成小红书帖子摘要；
- 展示小红书互动数据；
- 双按钮“浏览器预览/打开小红书”；
- 自动判断是否安装小红书 App；
- 用户登录或授权小红书。

## 9. 用户故事与验收标准

### US-024：查看目的地的小红书游玩体验入口

**作为** 正在旅行中做选择的用户，  
**我希望** 每个目的地都有一个小红书入口，  
**以便** 我可以快速看看相关游玩体验。

验收标准：

1. 旅行成功结果中展示“小红书游玩体验”区域。
2. 每个候选目的地展示一个“小红书查看”按钮。
3. 页面不展示搜索词。
4. 页面不出现“核验”文案。
5. 点击“小红书查看”打开小红书搜索结果页。

### US-025：AI 不假装读取小红书

**作为** 用户，  
**我希望** AI 不把没有读取过的小红书内容当成依据，  
**以便** 我知道建议依据是否可靠。

验收标准：

1. AI 回复不出现“根据小红书帖子”等表达。
2. 页面不展示小红书帖子摘要。
3. 页面不展示小红书标题、评论或互动数据。
4. 高德交通摘要和 AI 建议保持可用。

## 10. 待确认问题

1. 展示标题是否使用“小红书游玩体验”？
2. 描述文案是否使用“以下是 {B} 和 {C} 的游玩体验入口，你可以打开看看近期大家怎么分享。”？
3. “小红书查看”是否只做一个按钮，不拆分浏览器预览/打开 App？
4. 链接是否使用 `https://www.xiaohongshu.com/search_result?keyword=...`？
5. 是否在 AI 建议中明确一句“游客体验部分基于通用认知”，还是只在页面区域弱提示？
